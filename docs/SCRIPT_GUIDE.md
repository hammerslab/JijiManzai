# 漫才の台本を書くときのガイド（脚本担当向け）

台本（`proto/<題材>.txt`）を書く前に読む。書き方の記号は `proto/hacker.txt` の頭にある。

## 決まりごと

- **人を傷つけない題材・ネタ**にする。からかう相手はボケ本人か、物・仕組み・AI。実在の人物・企業・事件・被害者は出さない
- **標準語**で書く（音声合成が標準語のため）。関西弁のツッコミは標準語に置き換える（「なんでやねん」→「なんでだよ！」）
- 尺は**約 3 分**（M-1 の予選と同じ。決勝は 4 分）。書いたら音声を作って長さを測り、足し引きする
- コンビは 2 組。**女性に関わる題材は女性コンビ、それ以外は男性コンビ**（台本の頭に `combo: female` / `combo: male`）。どちらも A がボケ、B がツッコミ
  - 男性：A＝痩せたアフロ（淡々とゆっくり）／B＝太ったモヒカン（ハキハキ）。叩くツッコミの頭は「ワッーーツ！」（英語の What?）
  - 女性：A＝小さく痩せたボブ（低く落ち着いて淡々と）／B＝小太りの金髪ギャル（高めでハキハキ）。叩くツッコミの頭は「えぐーー！」。
    ツッコミの語尾は、なるべく「じゃん」系で、場面で長さを変える：**じゃーーん**＝叩くツッコミと一番驚くところ／**じゃーん**＝気持ちを乗せるツッコミ／**じゃん**＝短く返す・すぐ次へ続ける
- 叩くツッコミ（`B!`）は 1 本に 5〜8 回くらい。多すぎると「ワッーーツ！」「えぐーー！」がくどくなる
  - 叩く強さは 3 段階：`B!`（ふつう）／`B!!`（強い）／`B!!!`（いちばん強い）。強いほど、ボケが遠く飛ぶ・深く折れる、効果音も強くなる。後ろほど強くしていき（エスカレーション）、最後のオチを `B!!!` にする。`B!!!` は 1 本に 1〜2 回まで
- **時事ネタを知らない人も置いていかない**
  - **最初の 30 秒以内に、お題の短い説明を入れる**（1〜2 文。何が・どれくらい話題か）。挨拶とつかみのすぐあとに、会話の流れで言う。
    説明役はツッコミが自然（「最近、〇〇って流行ってるじゃん？」「〇〇って知ってる？ ××のことなんだけど」）。ボケが間違った説明をして、ツッコミが正しく言い直す形でもよい（説明が笑いになる）
  - **説明しすぎない**（説明が多いとくどい）。サブのキーワードは、分かりにくいものだけ、セリフの中で一言添える程度でよい（なくてもよい。例：「CAPTCHA ね。消火栓とか選ばされる面倒くさいやつ」）
  - 数字や日付は、作る時点の事実に合わせる。古くなりやすい細かい数字（何%・何位）は、ネタの芯にしない
- 締めは「もういいよ！」→ 2 人で「どうも、ありがとうございましたー！」
- 台本の頭に `title:`（題名）と `theme:`（お題＝題材のキーワード）を書く。タイトル画面に「お題：〇〇」と題名が出る。題名は 15 字くらいまで（長いと字が小さくなる）
- 動画は決まった形：タイトル → 2 人が袖から登場 → **漫才（台本はここだけ。3 分以内）** → 袖へ退場 → エンディング。
  エンディング（名場面を流しながらチャンネル登録を頼む掛け合い）は、コンビごとに決まった台本（`proto/ending_male.txt` / `ending_female.txt`）で、毎回同じ。台本の中でチャンネル登録を頼まない
- 読み間違いを見つけたら、`BlackFairyTales/tools/config.json` の `readings.ja`（童話の動画と共通のリスト）に足す。その台本だけの読み方は `{表示|読み}` で書く

## 「」の声の使い分け（`「…」@スタイル`）

「」の中が**その場にいない誰か・機械の言葉**なら、別のキャラの声にする。**話し手が自分で言っている・まねしている**なら、話し手の声のまま調子だけ変える。
（声の中身は `proto/voices.json`。VOICEVOX のときは `voicevox.styles`）

| スタイル | 使う場面 | VOICEVOX の声 |
|---|---|---|
| `@robot` | 機械・AI・ロボットの返事、画像認証の文言 | Voidoll |
| `@system` | 案内・アナウンス（サイトの案内文、番号札の呼び出し、店内放送） | Voidoll（電話っぽい音） |
| `@shibui` | かっこつけた決めゼリフ、中二っぽい言い回し（ハッカーの「……侵入成功」など） | †聖騎士 紅桜† |
| `@jii` | お年寄りの言葉、昔の常識、説教、ことわざ（「昔は〇〇なんてなかったんじゃ」） | ちび式じい |
| `@cute` | 話し手が無理に作った高い声（配信の挨拶など） | 話し手のまま（高く・抑揚強め） |
| `@polite` | AI に打ち込む文などの、丁寧な棒読み | 話し手のまま（速く・平坦） |
| `@chappy` | AI っぽい口調のまね | 話し手のまま（速く・平坦） |
| `@whisper` | 小声 | 話し手のまま（小さく） |

別のキャラの声は、1 本に 2〜4 回まで（多いと誰の漫才か分からなくなる）。

## 題材の組み立て方（書き始める前に、どちらの型にするか決める）

### 型 1：メイン 1 つ ＋ サブ 3〜5 個（基本はこれ）

大きなテーマ（メイン）を 1 つ決め、そこから連想される用語・あるあるを 3〜5 個（サブ）並べて、1 つずつボケにしていく。
サブは**しょぼいものから大きいものへ**並べると、そのままエスカレーションになり、3 分の最後までネタが切れずにテンポよく上がっていく。

- 例：ハッカー（`proto/hacker.txt`）＝ ping（ただの確認）→ パスワードを忘れた方はこちら（正規の手順）→ 画像認証（人間の証明を AI にやらせる）→ 社内エクセル（しょーもない標的）→ 勤怠のハッキング（自分の首を絞める）
- 例：インフルエンサー ＝ フォロワー → 挨拶 → 映え写真 → ライブ配信 → 企業案件 → バズ
- 例：チャッピー構文 ＝ 口癖 → ポイントは 3 つ → 寄り添い → 太字 → 長文 → 堂々と嘘 → 感情はありません
- 台本を書く前に、サブの一覧と並び順を先に書き出してから始める

### 型 2：メイン 2 つの「ギャップ」

あえて関係のない 2 つのキーワードをぶつけ、噛み合わなさで笑いを作る。設定が新しくなりやすく、ボケのキャラも立てやすいが、難しい。

- 例：ハッカー × 農家 ＝ 農家がハッキングにはまり、サイバー空間で作物の自動給水システムを作ろうとするが、やっていることはただの朝の水やり
- 2 つのうち片方を「世界」（何をしているか）、もう片方を「中身」（実際にやっていること）にすると組み立てやすい
- **人を傷つけない注意**：ぶつける相手が職業・世代・地域など人の集まり（農家、おばあちゃん、など）のときは、その人たちを笑いものにしない。おかしいのはボケ本人の勘違いやずれで、相手の仕事や暮らしはむしろ「ちゃんとしている」側に置く
- 型 2 でも、サブ（その世界のあるある）を 3〜5 個用意して順にずらしていくと、型 1 と同じように最後まで持つ

## 使える技（1 本に全部入れなくてよい。題材に合うものを選ぶ）

### 掛け合いの技

| 技 | どういうものか | 台本での書き方・注意 |
|---|---|---|
| ノリツッコミ | ボケをすぐ否定せず、一度そのノリに乗って演じてから、強くひっくり返す | 乗る部分は B のセリフ（「」@スタイルで声を変えてもよい）、ひっくり返す「って、なんでだよ！」の行を `B!` にする。標準語で |
| たとえツッコミ | ボケのおかしさを、分かりやすい別の物事にたとえる「〇〇か！」 | たとえる先に実在の人物・作品名を使わない。誰でも分かる日常の物事にたとえる |
| ノリボケ | ツッコミの指図や振りに、ボケが想像以上に大げさに乗っかって膨らませる | B の振り（「じゃあやってみろよ」など）→ A の過剰な演技。A は淡々とした声のまま過剰なことを言うと、声との落差でさらに効く |
| 言い間違い・勘違い | 似た音の別の言葉にすり替える、意味を取り違えたまま話を進める | 音声合成の読み間違いと区別がつくよう、字幕にも出る言葉で書く。読みがぶれる言葉は `{表示\|読み}` で読みを決める |
| すれ違い | 2 人が別の前提を思い浮かべたまま、噛み合っているようでずれた会話を続ける | どこで種明かしするかを先に決めてから書く。ずれは 3〜4 往復くらいで明かす |

### 構成の技

| 技 | どういうものか | 台本での書き方・注意 |
|---|---|---|
| 天丼 | ウケたボケ・フレーズを、少し時間を置いてもう一度繰り返す | 2 回目は少し形を変えるか、間を変える。3 回目まで行くなら、3 回目でひねる |
| 伏線回収（かぶせ） | 前半に何気なく出したフレーズや小ネタを、後半の別の文脈で使う | 例：インフルエンサーの「ずっとコメントしてくれる人」→ オチで正体がツッコミ本人／チャッピー構文の「富士山の標高は気分で変わる」→ 最後の「お前が言うな！」 |
| スカシ | 大きなボケ・強いツッコミを予感させておいて、何も言わない・冷めた返事をする | 前の行を盛り上げてから、短い一言か無言の間（`(1.0)` など長めの間）。例：チャッピー構文の「……田中さんは、関係ないだろ。」（急に素に戻る） |
| エスカレーション | 同じ型の掛け合いを繰り返しながら、ボケの規模とツッコミの熱を 1 段ずつ上げる | 例：インフルエンサーのフォロワー → 挨拶 → 映え → 配信 → 案件 → バズ。後ろほど叩くツッコミ（`B!`）を増やす |

### 間とテンポの技

| 技 | どういうものか | 台本での書き方 |
|---|---|---|
| タメ | ツッコミや大ボケの直前に、一瞬（0.1〜0.5 秒）黙る | 行の頭の間を 0.3〜0.6 にする（`A(0.5):`）。セリフの途中なら `[pause short]` |
| 一拍空け | ボケを受けて、すぐ反応せず「ん？」という間を挟む | `B(0.4): ……え？` のように、短い反応を間のあとに置く |
| スルー | 明らかなボケに反応せず、そのまま話を進める。あとで「スルーすんな！」と回収してもよい | B は何事もなかったように次の話をする。回収するなら数往復あとで `B!` |
| スカシの間 | 激しいツッコミが来ると思わせて、無音・無反応を通す | 長い間（`(1.0)` 以上）だけを置き、次の行で別の話に移る |
| 食い気味 | ボケの語尾が終わる手前で、かぶせてツッコむ | ボケの次のツッコミは、何も書かなければ 0.1 秒かぶる。叩くツッコミ（`B!`）は 0.15 秒。もっと食うなら `B(-0.2):` |
| 畳み掛け | 短いボケとツッコミを、かぶせ気味に矢継ぎ早に交互に出す | 1 行を短く（10 文字前後）し、両方の間をマイナス（`A(-0.05):` `B(-0.1):`）にして 4〜6 往復続ける |
| 被せ（言葉の重ね） | 相手が話している最中に、同じ言葉や別のツッコミを上から重ねる | 大きくマイナスの間で、前の行の途中から重ねる（`B(-1.0):` で前のセリフの終わり 1 秒前から）。重ねすぎると聞き取れないので要所だけ |
| 緩急 | 速い掛け合いの途中で、急にゆっくり話す | 畳み掛けのあとに、ボケの長めのセリフを `A(0.6):` で置く。ボケの声はもともと遅いので落差が出やすい |

### 声と画の落差

- **音の大小・高低**：ボケは低く小さく淡々と、ツッコミは高く大きく食いつく。声の設定（`proto/voices.json`）ですでにそうしてある。台本では、ボケに「！」を多用しない（淡々さが崩れる）
- **見つめ合う間（ガン見）**：無言の間を、2 人が見つめ合って「意味のある間」にする。台本では、その位置に 1 行で `(見つめ合う 1.2)` と書く（秒は 0.8〜1.5 くらい）。
  黙っている間と、そのあとの 1 行のあいだ、2 人とも相手を見て少し相手のほうへ傾く。次の行の間は書かなければ 0。
  スカシ・一拍空け・種明かしの直前に効く。1 本に 1〜2 回まで（多いとテンポが落ちる）。
  例：チャッピー構文の「田中さんの話、3時間してたじゃねえか！」→ 見つめ合う → 「……田中さんは、関係ないだろ。」／インフルエンサーの「ずっとツッコんでる人が、面白いって。」→ 見つめ合う → 「……え？」

## 書いたあとに確かめること

1. `python proto/synth.py proto/<題材>.txt` で音声を作り、長さが約 3 分か見る（足りなければネタを足し、長ければ一番弱いくだりを外す）
2. 「長すぎる声」の警告が出ていないか（音声合成が語尾を何秒も伸ばすことがある。伸ばし棒を 2 本以上続けると起きやすい）
   VOICEVOX で作るときは `python proto/vv_kana.py <題材>` で全行の読みをカナにして、読み間違いを探す（`build/kana/<題材>.txt`）。見つけたら共通のリストに足す。言い回しを少し変える（助詞を足すなど）と直ることも多い（例：「コート出しちゃった」→「コートを出しちゃった」）
3. 人を傷つける言い方・実在の人物や企業が入っていないか、もう一度読む
